# AGENTS.md

NovaCore is a Lithuanian-language mobile web app (PWA) built around a camera game: phone camera -> MediaPipe Pose -> squat, jumping-jack, high-knee, squat-jump, side-step, reverse-lunge, and standing cross-crunch counting for 1-2 players. Since 2026-10-25 (branch `app-v1`) it is a **Vite + TypeScript** project (vanilla, no UI framework). Dependencies: `vite`, `typescript`, `@mediapipe/tasks-vision` pinned to **0.10.14** (JS bundled from npm; the wasm and the pose model still load from CDNs at runtime; fonts are bundled in `public/fonts`), `@supabase/supabase-js` pinned to **2.118.0** (online layer: nickname, kompanijos, weekly leaderboard, challenges).

## Run and verify

- `npm install`, then `npm run dev` (Vite dev server, `http://localhost:5173`), `npm run build` (-> `dist/`), `npm run preview` (serves `dist/`). Camera requires a secure context: localhost works, a phone over LAN needs HTTPS (or use the Vercel preview).
- `npm test` = `tsc` (typecheck) + `node test-detect.cjs` (synthetic poses, prints `OK`) + `node test-stats.cjs` (streaks, week, badges; prints `OK`) + `node tools/replay-check.cjs` (real-person clips in `tools/fixtures/*.json`, prints `OK`; uses `public/pose-samples.json` exactly like the game). Needs **Node >= 22.18** (the `.cjs` checks `require()` the `.ts` modules directly: built-in type stripping + require(esm)). Run after changing anything in `src/detect/`, `highlightSegments()`, `clipSpec()`, the classifier, or `tools/samples-spec.json`. `node tools/accuracy.cjs` prints per-case true count vs hand-written `step()` vs k-NN classifier and marks held-out cases - use it to decide which counter an exercise should use. The replay check is the one that catches "works on synthetic poses, fails on a real body" - see `tools/README.md` for how to add a clip.
- App screens: `npm run build && node tools/screens.cjs [cam.y4m] --both [--out dir]` screenshots EVERY screen and tab (onboarding 1-3, home empty/populated/challenge, Kompanijos empty/created/leaderboard/list, Pratimai, Profilis + badges + settings, history and nickname sheets, setup, exercise sheet, and with a camera file loading/ready/game/results/clips/home-after-game) in portrait 390×844 and landscape 844×390, with mocked Supabase (`tools/mock-supabase.cjs`) and a seeded history; look at every image. `--no-game` stops at the setup screen.
- Navigation: `npm run build && node tools/nav-check.cjs [cam.y4m]` (headless, mocked Supabase): tabs, deep link, push/pop transition (both screens present mid-slide), back from a group, sticky bar `.scrolled`, exercise detail sheet + Esc, and with a camera file back during ready / mid-game, results, "Žaisti dar kartą", back to Pradžia. Prints `N/N OK`, exit 1 on any failure. Run after touching `router.ts`, `game.ts` back handling or screen markup.
- Game flow only: `npm run build && node tools/playthrough.cjs <cam.y4m> [--landscape]` (headless Chrome with a fake camera fed from a video file, against the BUILT app in `dist/`; screenshots of every screen from `00-start` to `07-clips-menu` land in `_playthrough/`, ignored by git). It is the only way to see the ready/game/end/clips screens without a phone. See `tools/README.md`.
- Online layer: `node tools/social-check.mjs` runs against the REAL Supabase from `.env.local` (2 anonymous users, profiles, group, join by code, games, leaderboard, challenge, RLS asserts; deletes its group, the test users stay). Exit 0 = OK, 1 = failed, 2 = server not ready (migration not run or anonymous sign-ins disabled). `tools/screens.cjs` (always mocked) covers the online screens; `playthrough.cjs --social` mocks Supabase and opens a challenge link so `05-end` shows the comparison. Both skip or walk through the onboarding (`novacore.onb`).

Use `--gpu` (d3d11): on swiftshader MediaPipe runs ~1 inference/s, so the runners barely move. The y4m needs ~14 s with both wrists above the nose (a still frame works; two mirrored copies of one photo are often detected as ONE pose, test with `tools/extract.cjs --poses 2` first), ~1.5 s standing, then high knees. The first run after a cold start can miss the arms-up window while the model loads; rerun.

## Android app (Capacitor, 2026-10-25)

- `android/` is the committed Capacitor 8 project (`@capacitor/core|cli|android` 8.5.3, plugins `app`, `filesystem`, `share`; all exact). `capacitor.config.json` is the ONLY place for `appId` (`lt.novacore.app`) and `appName` - `android/app/build.gradle` reads both (applicationId + `resValue` strings; there is no `strings.xml`). The Java namespace `lt.novacore.app` (MainActivity package) is separate and does not need to change with the appId. Build outputs, `assets/public` and generated configs are git-ignored.
- **The same web code runs on Vercel and in the WebView.** Native-only behaviour is a `Capacitor.isNativePlatform()` branch, never a separate build; the web path must stay exactly as before. Current branches: `main.ts` (no service worker; Android back button -> `history.back()` when the WebView can go back, else `App.exitApp()` - the router handles it like the on-screen back), `clips.ts` (`nativeShare()`: blob `<a download>` does nothing in Android WebView and `navigator.share` is missing, so download menu + share write the clip to `Directory.Cache` in 3 MB base64 chunks and open the system share sheet), `social.ts` (`WEB` = `https://novacore-two.vercel.app` for invite/challenge links because the app's origin is `https://localhost`; links shared via `@capacitor/share`), `fullscreen.ts` (button hidden: Capacitor's WebChromeClient ends element fullscreen immediately).
- Camera: `CAMERA` in AndroidManifest; `BridgeWebChromeClient.onPermissionRequest` asks for the runtime permission on the first `getUserMedia` and then grants the WebView request. `getUserMedia` uses `audio:false` everywhere, so no `RECORD_AUDIO` - keep it that way unless a feature really records sound. Wake Lock does not exist in WebView: `MainActivity` sets `FLAG_KEEP_SCREEN_ON` for the whole app. Safe areas: Capacitor's SystemBars (default `insetsHandling: css`) either passes the insets to `env(safe-area-inset-*)` (WebView >= 140 + `viewport-fit=cover`) or pads the WebView, so the CSS needs no change.
- After any web change: `npm run build && npx cap sync android` (copies `dist/` into the APK). CI (`.github/workflows/android.yml`, Node 24, JDK 21) does `npm ci`, `npm test`, `npm run build` (with `VITE_SUPABASE_*` repo secrets), `npx cap sync android`, `./gradlew assembleDebug` and uploads the artifact `novacore-debug-apk` on every push to `master`/`android`. Debug-signed with the committed `android/app/debug.keystore` (public, password `android`; one fixed key so a newer APK installs over the old one - CI would otherwise make a random key per run). A Play Store build needs a real release keystore kept out of git.
- Not done yet: deep links (`/?g=` `/?c=` open the web app, not the APK - needs an intent filter / App Links + `App.addListener("appUrlOpen")`), offline first start (MediaPipe wasm + model still come from CDNs; bundle them into `public/` for offline), app icon/splash (Capacitor defaults; `@capacitor/assets` can generate them from `public/icons`).

## Navigation (app-v2, 2026-10-25)

- **Router** (`src/ui/router.ts`): hash routes `#/` Pradžia, `#/kompanijos`, `#/kompanijos/<group id>`, `#/pratimai`, `#/profilis`, `#/zaisti` (setup = `#start`). Query params stay before the hash, so `/?g=CODE` and `/?c=<id>` keep working with any route. Modules register `onView(view, fn)`; the hook runs every time the screen is shown (render from local data, then refresh from the network). `refresh()` re-runs the current hook (after a nickname change, clearing history).
- **History contract:** `history.state.d` = entries this tab pushed. `go(hash)` pushes, `go(hash,true)` replaces. Tabs replace each other, only Home stays below (back from any tab = Pradžia, then the app closes). The Home tab and "Į pradžią" call `home()` = `history.go(-d)`, never a duplicate home entry. Links with `data-back` use `history.back()` when `d>0`, so the on-screen back and Android back are the same action. Back restores the previous scroll position.
- **Not routes:** the onboarding (`showOnly("onb")`, first run only; `novacore.onb`; earlier players with history/nickname skip it; Profilis → "Kaip žaisti" reopens it) and the game flow. Entering `#ready` pushes one `#/zaidimas` entry (`state.game`). `setBackHandler()` in game.ts: back while readying = `backToSettings()`, back mid-game is swallowed (re-push), back on results/clips = `resetGame()` and the router shows the popped route. `#readyBack` calls `history.back()`.
- **Transitions (app-v3):** `show()` marks the entering screen `data-enter` and keeps the previous one visible for `MOTION_MS` with `data-leave` (+ `inert`): `fwd`/`back` = native push/pop slide (`--duration-medium`, `--ease-smooth-out`, the old screen drifts 24% and dims), between two tab roots (`ROOTS`) = `tab` (short fade + 8px rise, no slide, like iOS tabs), replace/deep link = `in`, first paint = none. `settle()` hides the leaving screen and clears the marks; `leaveApp()` settles first. Camera screens and `#end` use `modal-in` (fade + scale .96). Sheets slide up from 100% (`zen-sheet-in`, 400 ms) and down in 200 ms; `sheet()` in dom.ts is the shared open/close helper.
- **Sticky top bar:** every app screen starts with `<header class="nav">` inside `.wrap` (sticky, owns the top safe area). Tab roots have a large title (`h1.large-title`) below it and a hidden compact `.nav-title` that fades in when the screen gets `.scrolled` (router.ts: one capturing scroll listener, `scrollTop>40`); sub-screens (`#start`, `#group`) use `.nav.inline` with a back button and the h1 as the inline title. Pradžia wraps its content in two `.col` (display:contents in portrait, two columns in landscape).
- `body.ingame` hides the tab bar (camera flow); `body[data-view]` = current view (`onb` hides the tab bar too). App screens end above the tab bar (`.screen.app{bottom:var(--tb-h)}`), so nothing scrolls under it. The fullscreen button exists only in the camera flow.
- **Quick start** tiles on Pradžia click the same `[data-p]`/`[data-d]` buttons as the setup screen (state stays in sync) and call `startFlow()`. "Žaisti dar kartą" = `resetGame()` + `startFlow()` (no reload: scores, step state, clips, object URLs and the model are reset; `clips.ts` ignores late results via a generation counter).
- Checked by an interactive Playwright-style run (tabs, deep link, back during ready / mid-game / results, play again, Į pradžią): see CHANGELOG 2026-10-25 app-v2.

## Module rules (replace the old "sliced index.html" test harness)

- `src/detect/*` and `src/clips/highlight.ts` stay PURE: no `document`/`window`/`navigator`/`localStorage`, no imports from `ui/`, `game/`, `camera/`. The Node checks import them directly; anything DOM there breaks `npm test`.
- Relative imports use the `.ts` extension (`./step.ts`) - required by Node's type stripping; only erasable TypeScript syntax (no `enum`, `namespace`, parameter properties; `tsconfig` enforces `erasableSyntaxOnly`).
- Cross-module mutable state lives only in `S` (`src/game/state.ts`); module-private state stays a local `let`. `lastPoses` in `camera.ts` is an exported live binding (read-only for importers).
- Each UI module wires its own DOM on import (module scripts run after the markup is parsed); `main.ts` decides the import order.
- `any` is acceptable at the MediaPipe / vendor-prefixed DOM boundary; pure detection code is typed.
- `POSE` is filled outside the pure modules (`fetch("pose-samples.json")` in `main.ts`, `tools/replay.cjs` in Node).

## Detection and game logic

- The camera is FRONT-facing, which changes what is measurable: the 2D knee angle barely moves in a real squat (180→150), so squat/squat-jump depth uses `knee3()` (3D angle via MediaPipe `z`, swings ~130→60, standing reads 125-150 not 180) OR the 2D angle, with `KNEE_DOWN3/UP3/DOWN2/UP2` constants. Crouch via hip/shoulder ratio is noise from the front (do not reintroduce). Lunges are separated from squats by knee stagger, not stance width (ankles are 1.5-3.5 hip widths apart from the front). Cross-crunch checks the elbow dropping to knee HEIGHT (dy), not horizontal proximity. All of this came from `tools/fixtures`; retune against them, not by intuition.

- `step(s, lm, ex, now)` is the pure per-player state machine (`S.st`, one object per player); `detect()` sets `st[i].ar` (detection frame width/height) and adds `score[i] += multiplier`.
- Two counters live in `step()`. If `POSE[ex]` exists, the k-NN pose classifier counts (port of Google MediaPipe "Pose classification", Apache-2.0: `poseEmbed()` 23 normalized pair differences → `poseClassify()` top-30 max / top-10 mean distance vs labelled sample poses → time-based EMA (`CLS_TAU`) → a rep when a `count` class rises above `CLS_ENTER` votes and falls below `CLS_EXIT`). Otherwise the hand-written branch runs; it is also the fallback when `pose-samples.json` fails to load. Visibility gating (`NEED`/`VIS`) and `MIN_GAP` apply to both.
- Sample poses: `tools/samples-spec.json` lists, per exercise, labelled time ranges on fixtures (`down`/`up`/`L`/`R`, `no` = negatives from other exercises) plus `flip`, `count` and optional `pairs` (embedding pairs to use: squat and knees use legs+torso only so arm style does not matter). `node tools/samples.cjs` writes the `live:true` exercises to `pose-samples.json` (~60 KB). Adding or retuning an exercise = record a front-view clip, `tools/extract.cjs`, label time ranges, regenerate – not new thresholds. Keep held-out clips out of the spec so `accuracy.cjs` stays honest.
- Live on the classifier (2026-10-25): `squat`, `lunge`. Hand-written: `jack` (5 real front-view clips since detect-v4, 41/41), `knees`, `crunch` (classifier was not better on held-out clips), `squatjump` and `sidestep` (the embedding is translation-invariant, so a hop or sideways travel is invisible to it). `tools/accuracy.cjs` `STEP_TUNED` lists the clips each hand-written branch was tuned on; add to it whenever you tune on a clip so held-out numbers stay honest.
- Before each game, `readyLoop()` gates the start: every selected player must have both wrists above the nose (`armsUp()`) continuously for `READY_MS=3000`, with a `READY_GRACE=300` ms tolerance for detection dropouts. This replaces the old 3-2-1 countdown.
- `NEED` lists landmarks that must be visible above `VIS=0.5`; otherwise `s.lost` stops reps and shows the "atsitrauk" hint.
- Tracking is camera-frame driven, not screen-refresh driven: `sampleCamera()` draws and infers only when `cam.currentTime` changes, lets inference follow the camera rate (target ~60 fps, `DETECT_TARGET=16`), and widens `detectGap` when a detection takes long so low-end phones keep rendering. Pose inference runs on `detCv`, a copy capped at 1280 px on its long side, so a 1080p preview does not force MediaPipe to upload a 1080p texture while 720p detection stays unchanged. Keep camera/pose work inside the fresh-frame branch of `loop()` / `readyLoop()`; HUD text and the progress bar are throttled separately (`lastHudSec`, `lastBarAt`).
- The camera is requested with `width/height/frameRate` ideal at **1920×1080 / 60 fps**. After `getUserMedia()`, `getSettings().frameRate` plus the video dimensions determine the real mode; the browser is allowed to fall back. `clipSpec(videoW,videoH,fps,portrait)` then picks the clip tier: 1080p60 (`1080×1920`/`1920×1080`), 1080p30, 720p60, or 720p30. The live canvas always uses the camera's native dimensions. Recording draws on fresh camera frames with `recFrameMs` (15 ms at 60 fps, 28 ms at 30 fps), and the skeleton is one batched `stroke()` per player, not one per bone; line width and the P label scale from the 720px short-side baseline so 1080p previews do not get hairline overlays.
- `EX` entries may carry `beta:true`: shown in the picker with a BETA badge but excluded from the default `activeEX`. Drop the flag once the detection has been verified on a real person; the four exercises added on 2026-10-22 are still beta.
- Adding an exercise touches the `EX` table and `NEED` (`src/detect/exercises.ts`; the picker dialog renders its grid automatically from `EX`), a branch in `step()` (`src/detect/step.ts`), a `DEMO` entry (`src/ui/coach.ts`), the mascot pose + small icon in `src/ui/mascots.ts` (`POSES`, `ICON`, `EX_IDS`) with its `.anim.mp-<id>` keyframes in `src/styles/mascots.css`, and cases in `test-detect.cjs`.
- Poses are sorted by mirrored x (`1-lm[0].x`), so P1 is the leftmost player on screen. `numPoses` is fixed from the player count at start.
- Rounds are 30 s, multiplier is `1+round`, exercises cycle through the start-screen selection (`activeEX`, a non-empty subset of `EX`) starting at a random selected exercise (`exShift`) so with seven exercises in a 3-minute game (six rounds) the skipped one rotates between games; duration is 180 s with a 60 s test option. `#exOpen` summarizes the choice and opens the native `#exSheet` dialog; its `#exGrid` is regenerated from `EX` on every open (for the staggered `zen-tile-in` animation). Selection is multi-select, keeps `activeEX` in sync, persists in `localStorage`, and refuses to deselect the last exercise (deny wobble + note warning).
- Post-game flow is `#end` (results) -> `#toClips` -> `#clips` (highlight video + one download menu for preview/full + Web Share button). Both screens have `[data-again]` (Žaisti dar kartą) and `[data-home]` (Į pradžią). `#dlToggle` opens `#dlMenu`; `#sharePrev` shares the preview `File` via `navigator.share` and falls back to a download.
- `startRec()` records an offscreen canvas that mirrors only the camera, so clips never contain skeleton lines. It sizes the recording from the actual camera mode via `clipSpec()`: `1080x1920`/`1920x1080` when the camera gives at least 1080p, otherwise `720x1280`/`1280x720`; fps follows the camera (60 fps when it reports at least 50). It center-crops with `drawRecordFrame()`; `makeHighlightClip()` reuses `recCv` dimensions but always encodes at **30 fps** with the 30 fps bitrate tier (`clipSpec(out.w,out.h,30,…)`): the highlight is a preview/share clip and a real-time 60 fps re-encode overloads phones. Only the full clip keeps the camera fps. Never fall back to `cv.width/height` for clips.
- `REC_MIME` prefers MP4/H.264 level 4.2 (required for 1080p60), then lower H.264 levels, generic MP4, and finally WebM. Both recorders use the same MIME; the full recorder uses `clipProfile` fps/bitrate, the highlight recorder its 30 fps tier; high-quality clips are intentionally much larger. Download names/extensions come from `REC_EXT`.
- `highlightSegments()` chooses the highest-scoring 4 s bins but reserves one bin for every selected exercise present (`ROUND_SECS=30`, exercise count passed as the fifth argument); `finish()` passes `activeEX.length`, so easy or excluded exercises cannot dominate the reel. The full clip is finalized in `finish()`; the preview replays the full blob into a second canvas for 15–30 s. `playSegment()` draws on each decoded frame (`requestVideoFrameCallback`; rAF only as fallback, also when rVFC does not fire within 500 ms), not on every rAF. While the cut runs, `#previewVid` holds the full clip **paused** with a poster (first frame of the best segment, from `onPoster`) under the ETA overlay; never `play()` it then (a second 1080p60 decode next to the cut's decode + encode = stutter). It plays only on the player's own tap, or once the highlight is ready.
- `startFlow()` (Start / quick start / play again) shows `#loading` ("Kraunama") while camera/model initialize; it has a 700 ms minimum display and errors return to the app screen with a toast. Hide it only when `#ready` appears. Once the camera is negotiated, `#loadMsg` shows the actual mode (e.g. "Kamera 1080p · 60 fps") before the model finishes loading.
- `#demo` is the in-game exercise coach card, triggered from the round-change block via `showDemo(ex)`. `DEMO` covers every entry in `EX` (`squat`, `jack`, `knees`, `squatjump`, `sidestep`, `lunge`, `crunch`). The art is the animated vector mascot doing the exercise (`exArt(id)` in `src/ui/mascots.ts`, injected into `#demoArt`; loops in `mascots.css` `.anim.mp-<id>`); the same art is used in Pratimai and `#exDetail` (`coachSvg()`).
- Squat jumps (detect-v4): a squat with BOTH knees bent together (knee gap < 0.3 torso; running/high knees bend one at a time) → the LOWER foot rises `SJ_AIR`=0.2 torso above its squat floor (EMA of the ankle while squatting) → landing (foot back within `SJ_LAND` or knees bent again) after at least `SJ_FLIGHT`=200 ms airborne (a left/right ankle swap glitch lasts ~100 ms). No standing baseline: people jump straight from a resting squat (`squatjump3`); standing up from the squat alone never lifts the feet. Side steps: feet closed → open (lead foot > closedW + 1.5 hip widths) → closed again with the ankle center moved > 0.5 hip widths; "closed" = near the narrowest stance OR the valley after the feet came in below `SS_CLOSE`=0.55 of that step's widest spread (squat walks rarely close fully); no open-phase timeout (it re-based the center on the wide stance and counted a held side-squat stepping back in). No crouch gate. Reverse lunges require a hip drop plus staggered knees, so a level-knee squat does not count. High knees (detect-v4): one knee rises `KN_ON`=0.5 torso above the OTHER knee (not above the hip line: fast low knees only reach hip height), resets below `KN_OFF`=0.15, and when both ankles are visible the lifted foot must be `KN_FOOT`=0.6 torso above the other (a lunge's front knee is high but its foot stays down); MIN_GAP is halved for knees only (fast alternating steps ~0.27 s apart), one leg still cannot count twice without the other knee coming up. Standing cross-crunches require the knee to lift above 10% of torso length AND 0.5 torso above the other knee (a squat at an angle lifts both), with the opposite elbow at knee height (dy < 0.8 torso, dx < 1.3 shoulder widths); the knee must lower before that side can score again.
- `#demo` and `#hintCue` can be visible at the same time. The hint cue is placed above the demo card in portrait, and in phone landscape it becomes a compact row tucked below the demo card, so it never covers the exercise animation.
- Jumping-jack detection is strict on purpose: both arms must be above the head and swung outward, and both ankles must move outward from their own hip (`NEED` includes hips 23/24). A single stepping foot or hands-up-only motion must not count.
- `#readyBack` calls `backToSettings()`: stops the camera, cancels the readiness RAF and pending start timer, closes the landmarker, resets the ring/chips, and shows `#start` so settings can be changed before another Start.
- `keepScreenAwake()` requests the Screen Wake Lock when readiness starts and reacquires it on visibility changes. `releaseWakeLock()` must run on finish, back-to-settings, and startup errors; do not keep the lock on the results/clip screens.
- Prompt text (`#readyHint`, `#hint`) is now screen-reader-only; visible guidance is driven by `setCue()` into `#readyCue` / `#hintCue` with a bouncing arrow (`back`, `arms`, `left`, `right`). `sideCue()` checks core body points in mirrored screen space; keep the arrow direction and player labels in sync.
- If a player has not scored for ~5 s in a round, the current exercise demo is shown again once (`nudgedRound`, `IDLE_DEMO_SECS`). It may appear even while a movement cue is active.
- The fullscreen control hides itself when the Fullscreen API is missing and moves to the bottom-right while `body.playing` so it doesn't cover P2.

## Remote duels (branch `duel`, 2026-10-25)

- Two phones in different places play the same game at the same moment and see each other's score live. Transport = Supabase Realtime (broadcast + presence), not P2P; **video never leaves the phone** - only scores, ready/start/ping messages and presence. Solo and the same-phone 2-player game are untouched: everything hangs on `S.duel` (null outside a duel) and `body.duel`.
- **DB** (`002_duels.sql`, idempotent): `duels` (group_id, from_user, to_user, status pending|accepted|declined|cancelled|playing|done|expired, settings {duration 60|180, exercises[], seed}, scores 0-2000, winner). RLS: select only by the two players; NO direct insert/update grants - writes only through `invite_duel` (both members of the group via `is_member`, settings validated, 30 invites/h, one open invite per pair), `respond_duel` (invitee; older than 10 min -> `expired`), `cancel_duel`, `start_duel` (host), `finish_duel` (own score once, winner when both are in), `pending_duels()` (my valid invites + inviter nickname). `duels` is in the `supabase_realtime` publication (live invites/answers via postgres_changes, RLS applies). The channel `duel:<uuid>` is **private**: `realtime.messages` policies call `duel_topic_ok(realtime.topic())`, so only the two players can join, send or receive.
- **Flow:** Kompanijos -> group -> swords button on a member (`social.ts` lbRow adds `[data-duel]`) -> `#duelSheet` "pick" (1/3 min, current exercise selection) -> invite; the inviter waits on the channel ("wait"). Invitee: inbox channel `inbox:<uid>` (started only if `pending_duels` works, so a missing 002 never loops rejoins) pops the sheet ("incoming") unless a game/camera screen is up; otherwise the `#duelInv` card on Pradžia. Accept -> both in "lobby" (presence dots) -> "Į kamerą" = `enterCamera()`: saves and overrides `S.players=1`, duration, `activeEX` from the settings, sets `S.duel`, `startFlow()`. The arms-up gate is the camera-ready check: `finishReady()` hands over to `S.duel.ready(startGame)` ("Laukiam"; the camera keeps drawing via `sampleCamera`). Host, when both are ready: start = host `Date.now()+3000`, broadcast `start{at}`; the guest converts it with its clock offset (5 ping/pong when the host appears, fastest RTT, `clockOffset()`), both count down 3-2-1 and call `startGame()`; `exShift = seedShift(seed)` so the exercise order is identical. During play the own score is sent every 250 ms **only when it changed** (`SCORE_MS`); the opponent's score goes into `S.score[1]`, so the existing HUD renders it (P1 red = you, P2 blue = opponent, chip = nickname). Presence drop -> chip "Atsijungė", the game continues. `finish()` -> `S.duel.finish()`: broadcast `final`, `finish_duel` RPC, `#end` shows both (winner, bars, `#duelRes` line) and waits up to 8 s for the opponent's final, then shows the last live score as "atsijungė". "Revanšas" = a new invite with the same settings (crossing rematches: the second one auto-accepts). `resetGame()` / `backToSettings()` / startup errors call `S.duel.end()`: restores the saved settings, leaves the channel, `bye` + `cancel_duel` if it never started.
- **Offline:** no `sb` or `navigator.onLine===false` -> toast "Dvikovai reikia interneto..."; the swords buttons only exist when the leaderboard has loaded.
- **Messages budget (free tier: 2 M messages/month, 200 concurrent connections):** measured with `tools/duel-ui.cjs` for a 1-min duel: presence 2-3, ping+pong 10, ready 2, start 1, final 2, score ~50 (both players together), postgres_changes 6-12 (invite, answer, start, finish rows). A 3-min duel = ~25 control + score sends (max 4/s per player, typically ~1/s while moving) = ~300-450 sent, roughly doubled because delivered messages count too -> **~600-900 per duel, worst case ~3 000** (4/s x 2 players x 180 s, x2) -> at least ~650 duels/month even in the worst case. Never send per frame; skeleton/avatar streaming is NOT implemented (it would be ~10 msg/s per player).
- **Rules:** never the service_role key; validate anything from the other phone (`sc()` clamps scores; the server checks the bounds again); duel code stays in `src/duel/` with the hook list in `state.ts` (`DuelHooks`); keep the `game.ts` part to the six one-line `S.duel?.` calls. Clock sync accuracy = half the round-trip asymmetry (typically < 50-100 ms on mobile networks); with no pong the offset is 0 (phone clocks are usually NTP-synced anyway).
- Known limits: an exercise id unknown to an older app version is skipped (the order could then differ - keep both apps updated); the client clock only hides stale invite cards (the server re-checks in `respond_duel`).

## Sprintas 100 m (branch `sprint`, 2026-10-25)

- **Flow:** Pradžia tile (`.sp-tile`, injected after `#homePlay`) → route `#/sprintas` (`#sprint`: 2 = duel / 1 = vs ghost, personal best, how-to, live rig preview) → `startFlow(SPRINT)` → the normal `#loading` + `#ready` arms-up gate → `SPRINT.start()` → `#sprintRun` (canvas + HUD) "Į starto pozicijas" 1.7 s → "Dėmesio…" 1.3–2.3 s (random) → "Marš!" (`sfx.gun`) → race → `#sprintEnd`. A knee lift during "Dėmesio" = false start ("Per anksti!", restart; max 2, then ignored).
- **Game-mode hook (game.ts):** `startFlow(mode?:GameMode)`; `GameMode={start,reset,shown}`. `startGame()` hands over to `mode.start()` after the ready gate, `resetGame()` calls `mode.reset()`, the back handler treats `mode.shown()` like `#end`. `S.running=true` during the countdown/race, so Android back is swallowed exactly like in the rep game. `#go` must call `startFlow()` with no argument (not with the click event).
- **Detection:** the existing `step(st,lm,"knees",now)` per player on fresh camera frames; every counted knee lift = one step (`onStep`). Nothing changed in `src/detect/`. Steps after the finish line are ignored, so runners coast to a stop.
- **Speed model (`src/sprint/speed.ts`, PURE, `test-sprint.cjs`):** cadence = EMA (0.35) of 1/Δt between steps, Δt outside 0.12–1.2 s ignored (detector jitter / not running); once the next step is overdue the cadence decays as 1.5/gap, 0 after 1.2 s. Target speed `v* = min(11.5, 2.6 × cadence)` m/s; speed eases toward it (τ 0.8 s up, 0.45 s down), acceleration capped at 6.5 m/s². 10 m splits and the finish time are interpolated inside the frame (frame-rate independent). Steady cadence → 100 m: 2.5/s 16.9 s · 3/s 14.3 s · 3.5/s 12.5 s · 4/s 11.1 s · 5/s 10.3 s. Retune `K_SPEED`/`V_MAX` there and keep the test ranges honest.
- **Ghost (solo):** replays the 10 m splits of the best sprint in history (`ghostX`); without one, `simulate(2.8)` ≈ 15.2 s ("Tikslinis laikas").
- **History:** sprint games are normal `novacore.history` rows with `mode:"sprint"`, `times` (s, null = did not finish), `splits` (10 per player), `reps`/`exReps.knees` = steps, `score:[0,0]` (point records ignore them; streaks, weekly goal and knee totals count them). `histItem()` prints "Sprintas 100 m · solo/dvikova" with the times; `saveHist` is exported for this. Not sent to Supabase.
- **Rendering:** one `<canvas>` (DPR ≤ 2, `alpha:false`). Stands (blurred crowd, roof, floodlights), ad boards and grass are painted once per resize into offscreen tiles (`build()`); a frame = sky fill + 3 tiled blits + track, lane lines, ticks, painted 25/50/75, checkered finish, tape/posts, runners, dust/confetti from preallocated Float32Array pools. Lines across the lanes lean with depth (`SKEW`) and a runner's screen x adds the same skew. Camera: frames both humans when they are within half a view, otherwise follows the leader WITH its speed added (no steady lag: the portrait view is only ~4 m wide); after the winner crosses it goes back for the runner still racing; off-screen runners get an edge pill with the gap ("Raudonas −14 m"). The HUD is DOM, updated every 80 ms, text only on change, bars/dots by transform. `#stage` (camera + skeletons) becomes a corner preview via `body.sprinting` (portrait: bottom-right on the grass; phone landscape: top-right over the stands, never over a lane).
- **Runner art (Claude Design):** `runner.ts` draws the vector mascot in side view on the canvas – round head with the headband and flapping knot tails, profile eye/brow/mouth, small body, floating gloves on the arm swing, navy capsule legs with sneakers, navy outline; far-side glove/leg darker. Same pose rig as before (forward-kinematics grounding, run-cycle phase at `0.2·v` cycles/s, stride/lean grow with speed, squash at contacts; set / stand / win poses). HUD faces and result rows use `avatar()`, the Pradžia tile and the result header `mascot()`. Canvas text uses Titan One (`document.fonts.load` with the "FINIŠAS" glyphs before the tiles are built).
- **Measured (headless Chrome, real GPU, 390×844 @2x, `sprint-check.cjs`):** solo 56–60 fps, duel 39–45 fps (MediaPipe with 2 poses dominates: work p95 ~45 ms); the scene itself costs 0.2–0.5 ms/frame (p95 < 2 ms).
