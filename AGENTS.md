# AGENTS.md

NovaCore is a Lithuanian-first mobile web app (PWA, Lithuanian + English UI, see **Languages / i18n**) built around a camera game: phone camera -> MediaPipe Pose -> squat, jumping-jack, high-knee, squat-jump, side-step, reverse-lunge, and standing cross-crunch counting for 1-2 players. Since 2026-10-25 (branch `app-v1`) it is a **Vite + TypeScript** project (vanilla, no UI framework). Dependencies: `vite`, `typescript`, `@mediapipe/tasks-vision` pinned to **0.10.14** (JS bundled from npm; the wasm and the pose model still load from CDNs at runtime; fonts are bundled in `public/fonts`), `@supabase/supabase-js` pinned to **2.118.0** (online layer: nickname, kompanijos, weekly leaderboard, challenges).

## Team workflow (Ignas+Claude and Martynas+his AI) — READ FIRST

Two people with two AI agents work on this repo. To never overwrite each other:

1. **Tasks live in GitHub Issues** (`gh issue list`). Labels: `Martynas`, `Ignas+Claude`, `telefono testas`, `iki 11-06`. Work only on an issue labelled for you; to take a new one, comment "imu" and add your label first.
2. **One issue = one branch** named `<who>/<issue#>-<short>` (e.g. `martynas/3-release-aab`, `claude/7-boxing-badge`). Never commit straight to `master`.
3. **Owned areas** (the other side changes them only via a PR the owner reviews): Martynas – `src/cast/`, `.github/workflows/android.yml`, `android/`; Ignas+Claude – everything else. Shared files (`index.html`, `src/main.ts`, `src/ui/router.ts`, `src/i18n/*`, `CHANGELOG.md`, `AGENTS.md`) – keep edits small, append, don't reformat.
4. **Before you start:** `git pull` on master, branch from it. **Before you push:** `npm test` (+ `npx tsc --noEmit`), then merge the latest `origin/master` into your branch and re-run. Merge to master only when CI (Tests + Android) is green; never force-push master.
5. **Close the issue** in the merge commit message (`closes #7`) and add a CHANGELOG line.

## Android app (Capacitor, 2026-10-25)

- `android/` is the committed Capacitor 8 project (`@capacitor/core|cli|android` 8.5.3, plugins `app`, `filesystem`, `share`; all exact). `capacitor.config.json` is the ONLY place for `appId` (`lt.novacore.app`) and `appName` - `android/app/build.gradle` reads both (applicationId + `resValue` strings; there is no `strings.xml`). The Java namespace `lt.novacore.app` (MainActivity package) is separate and does not need to change with the appId. Build outputs, `assets/public` and generated configs are git-ignored.
- **The same web code runs on Vercel and in the WebView.** Native-only behaviour is a `Capacitor.isNativePlatform()` branch, never a separate build; the web path must stay exactly as before. Current branches: `main.ts` (no service worker; Android back button -> `history.back()` when the WebView can go back, else `App.exitApp()` - the router handles it like the on-screen back), `clips.ts` (`nativeShare()`: blob `<a download>` does nothing in Android WebView and `navigator.share` is missing, so download menu + share write the clip to `Directory.Cache` in 3 MB base64 chunks and open the system share sheet), `social.ts` (`WEB` = `https://novacore-two.vercel.app` for invite/challenge links because the app's origin is `https://localhost`; links shared via `@capacitor/share`), `fullscreen.ts` (button hidden: Capacitor's WebChromeClient ends element fullscreen immediately).
- Camera: `CAMERA` in AndroidManifest; `BridgeWebChromeClient.onPermissionRequest` asks for the runtime permission on the first `getUserMedia` and then grants the WebView request. `getUserMedia` uses `audio:false` everywhere, so no `RECORD_AUDIO` - keep it that way unless a feature really records sound. Wake Lock does not exist in WebView: `MainActivity` sets `FLAG_KEEP_SCREEN_ON` for the whole app. Safe areas: Capacitor's SystemBars (default `insetsHandling: css`) either passes the insets to `env(safe-area-inset-*)` (WebView >= 140 + `viewport-fit=cover`) or pads the WebView, so the CSS needs no change.
- After any web change: `npm run build && npx cap sync android` (copies `dist/` into the APK). CI (`.github/workflows/android.yml`, Node 24, JDK 21) does `npm ci`, `npm test`, `npm run build` (with `VITE_SUPABASE_*` repo secrets), `npx cap sync android`, `./gradlew assembleDebug` and uploads the artifact `novacore-debug-apk` on every push to `master`/`android`. Debug-signed with the committed `android/app/debug.keystore` (public, password `android`; one fixed key so a newer APK installs over the old one - CI would otherwise make a random key per run). A Play Store build needs a real release keystore kept out of git.

## Detection and game logic

- The camera is FRONT-facing, which changes what is measurable: the 2D knee angle barely moves in a real squat (180→150), so squat/squat-jump depth uses `knee3()` (3D angle via MediaPipe `z`, swings ~130→60, standing reads 125-150 not 180) OR the 2D angle, with `KNEE_DOWN3/UP3/DOWN2/UP2` constants. Crouch via hip/shoulder ratio is noise from the front (do not reintroduce). Lunges are separated from squats by knee stagger, not stance width (ankles are 1.5-3.5 hip widths apart from the front). Cross-crunch checks the elbow dropping to knee HEIGHT (dy), not horizontal proximity. All of this came from `tools/fixtures`; retune against them, not by intuition.

- `step(s, lm, ex, now)` is the pure per-player state machine (`S.st`, one object per player); `detect()` sets `st[i].ar` (detection frame width/height) and adds `score[i] += multiplier`.
- Two counters live in `step()`. If `POSE[ex]` exists, the k-NN pose classifier counts (port of Google MediaPipe "Pose classification", Apache-2.0: `poseEmbed()` 23 normalized pair differences → `poseClassify()` top-30 max / top-10 mean distance vs labelled sample poses → time-based EMA (`CLS_TAU`) → a rep when a `count` class rises above `CLS_ENTER` votes and falls below `CLS_EXIT`). Otherwise the hand-written branch runs; it is also the fallback when `pose-samples.json` fails to load. Visibility gating (`NEED`/`VIS`) and `MIN_GAP` apply to both.
- Sample poses: `tools/samples-spec.json` lists, per exercise, labelled time ranges on fixtures (`down`/`up`/`L`/`R`, `no` = negatives from other exercises) plus `flip`, `count` and optional `pairs` (embedding pairs to use: squat and knees use legs+torso only so arm style does not matter). `node tools/samples.cjs` writes the `live:true` exercises to `pose-samples.json` (~60 KB). Adding or retuning an exercise = record a front-view clip, `tools/extract.cjs`, label time ranges, regenerate – not new thresholds. Keep held-out clips out of the spec so `accuracy.cjs` stays honest.
- Live on the classifier (2026-10-25): `squat`, `lunge`. The lunge k-NN counter has one extra gate in `step()` (detect-v5): the EMA knee stagger (`|y25-y26|`/torso) must reach `LG_STAG`=0.25 while in `down` - the embedding sees a wide side-step / squat-walk stance as a lunge (sidestep clips: 17/6/10 false lunges -> 0; real lunges peak 0.30-0.88). `tools/accuracy.cjs` `GATE_TUNED` lists the clips that gate was tuned on (not held-out for k-NN). Hand-written: `jack` (5 real front-view clips since detect-v4, 41/41), `knees`, `crunch` (classifier was not better on held-out clips), `squatjump` and `sidestep` (the embedding is translation-invariant, so a hop or sideways travel is invisible to it). `tools/accuracy.cjs` `STEP_TUNED` lists the clips each hand-written branch was tuned on; add to it whenever you tune on a clip so held-out numbers stay honest.
- Before each game, `readyLoop()` gates the start: every selected player must have both wrists above the nose (`armsUp()`) continuously for `READY_MS=3000`, with a `READY_GRACE=300` ms tolerance for detection dropouts. This replaces the old 3-2-1 countdown.
- `NEED` lists landmarks that must be visible above `VIS=0.5`; otherwise `s.lost` stops reps and shows the "atsitrauk" hint.
- Tracking is camera-frame driven, not screen-refresh driven: `sampleCamera()` draws and infers only when `cam.currentTime` changes, lets inference follow the camera rate (target ~60 fps, `DETECT_TARGET=16`), and widens `detectGap` when a detection takes long so low-end phones keep rendering. Pose inference runs on `detCv`, a copy capped at 1280 px on its long side, so a 1080p preview does not force MediaPipe to upload a 1080p texture while 720p detection stays unchanged. Keep camera/pose work inside the fresh-frame branch of `loop()` / `readyLoop()`; HUD text and the progress bar are throttled separately (`lastHudSec`, `lastBarAt`).
- The camera is requested with `width/height/frameRate` ideal at **1920×1080 / 60 fps**. After `getUserMedia()`, `getSettings().frameRate` plus the video dimensions determine the real mode; the browser is allowed to fall back. `clipSpec(videoW,videoH,fps,portrait)` then picks the clip tier: 1080p60 (`1080×1920`/`1920×1080`), 1080p30, 720p60, or 720p30. The live canvas always uses the camera's native dimensions. Recording draws on fresh camera frames with `recFrameMs` (15 ms at 60 fps, 28 ms at 30 fps), and the skeleton is one batched `stroke()` per player, not one per bone; line width and the P label scale from the 720px short-side baseline so 1080p previews do not get hairline overlays.
- `EX` entries may carry `beta:true`: shown in the picker with a BETA badge but excluded from the default `activeEX`. Drop the flag once the detection has been verified on a real person; the four exercises added on 2026-10-22 are still beta.
- Adding an exercise touches the `EX` table and `NEED` (`src/detect/exercises.ts`; the picker dialog renders its grid automatically from `EX`), a branch in `step()` (`src/detect/step.ts`), its tone in `TONE` (`src/ui/coach.ts`; `DEMO` is built from it) plus `ex.<id>` / `cue.<id>` / `tip.<id>` in BOTH `src/i18n/lt.ts` and `en.ts`, the mascot pose + small icon in `src/ui/mascots.ts` (`POSES`, `ICON`, `EX_IDS`) with its `.anim.mp-<id>` keyframes in `src/styles/mascots.css`, and cases in `test-detect.cjs`.
- Poses are sorted by mirrored x (`1-lm[0].x`), so P1 is the leftmost player on screen. `numPoses` is fixed from the player count at start.
- Rounds are 30 s, multiplier is `1+round`, exercises cycle through the start-screen selection (`activeEX`, a non-empty subset of `EX`) starting at a random selected exercise (`exShift`) so with seven exercises in a 3-minute game (six rounds) the skipped one rotates between games; duration is 180 s with a 60 s test option. `#exOpen` summarizes the choice and opens the native `#exSheet` dialog; its `#exGrid` is regenerated from `EX` on every open (for the staggered `zen-tile-in` animation). Selection is multi-select, keeps `activeEX` in sync, persists in `localStorage`, and refuses to deselect the last exercise (deny wobble + note warning).
- Post-game flow is `#end` (results) -> `#toClips` -> `#clips` (highlight video + one download menu for preview/full + Web Share button). Both screens have `[data-again]` (Žaisti dar kartą) and `[data-home]` (Į pradžią). `#dlToggle` opens `#dlMenu`; `#sharePrev` shares the preview `File` via `navigator.share` and falls back to a download.
- `startRec()` records an offscreen canvas that mirrors only the camera, so clips never contain skeleton lines. It sizes the recording from the actual camera mode via `clipSpec()`: `1080x1920`/`1920x1080` when the camera gives at least 1080p, otherwise `720x1280`/`1280x720`; fps follows the camera (60 fps when it reports at least 50). It center-crops with `drawRecordFrame()`; `makeHighlightClip()` reuses `recCv` dimensions but always encodes at **30 fps** with the 30 fps bitrate tier (`clipSpec(out.w,out.h,30,…)`): the highlight is a preview/share clip and a real-time 60 fps re-encode overloads phones. Only the full clip keeps the camera fps. Never fall back to `cv.width/height` for clips.
- `REC_MIME` prefers MP4/H.264 level 4.2 (required for 1080p60), then lower H.264 levels, generic MP4, and finally WebM. Both recorders use the same MIME; the full recorder uses `clipProfile` fps/bitrate, the highlight recorder its 30 fps tier; high-quality clips are intentionally much larger. Download names/extensions come from `REC_EXT`.
- `highlightSegments()` chooses the highest-scoring 4 s bins but reserves one bin for every selected exercise present (`ROUND_SECS=30`, exercise count passed as the fifth argument); `finish()` passes `activeEX.length`, so easy or excluded exercises cannot dominate the reel. The full clip is finalized in `finish()`; the preview replays the full blob into a second canvas for 15–30 s. `playSegment()` draws on each decoded frame (`requestVideoFrameCallback`; rAF only as fallback, also when rVFC does not fire within 500 ms), not on every rAF. - `#demo` is the in-game exercise coach card, triggered from the round-change block via `showDemo(ex)`. `DEMO` covers every entry in `EX` (`squat`, `jack`, `knees`, `squatjump`, `sidestep`, `lunge`, `crunch`). - Squat jumps (detect-v4): a squat with BOTH knees bent together (knee gap < 0.3 torso; running/high knees bend one at a time) → the LOWER foot rises `SJ_AIR`=0.2 torso above its squat floor (EMA of the ankle while squatting) → landing (foot back within `SJ_LAND` or knees bent again) after at least `SJ_FLIGHT`=200 ms airborne (a left/right ankle swap glitch lasts ~100 ms). No crouch gate. Reverse lunges require a hip drop plus staggered knees, so a level-knee squat does not count. ## Sprintas 100 m (branch `sprint`, 2026-10-25)

- **Flow:** Pradžia tile (`.sp-tile`, injected after `#homePlay`) → route `#/sprintas` (`#sprint`: 2 = duel / 1 = vs ghost, personal best, how-to, live rig preview) → `startFlow(SPRINT)` → the normal `#loading` + `#ready` arms-up gate → `SPRINT.start()` → `#sprintRun` (canvas + HUD) "Į starto pozicijas" 1.7 s → "Dėmesio…" 1.3–2.3 s (random) → "Marš!" (`sfx.gun`) → race → `#sprintEnd`. A knee lift during "Dėmesio" = false start ("Per anksti!", restart; max 2, then ignored).
- **Game-mode hook (game.ts):** `startFlow(mode?:GameMode)`; `GameMode={start,reset,shown}`. `startGame()` hands over to `mode.start()` after the ready gate, `resetGame()` calls `mode.reset()`, the back handler treats `mode.shown()` like `#end`. `S.running=true` during the countdown/race, so Android back is swallowed exactly like in the rep game. `#go` must call `startFlow()` with no argument (not with the click event).
- **Detection:** the existing `step(st,lm,"knees",now)` per player on fresh camera frames; every counted knee lift = one step (`onStep(r,t,leg)`; `frame()` passes which knee went up by comparing `st.leg` before/after). Nothing changed in `src/detect/`. Steps after the finish line are ignored, so runners coast to a stop.
- **Speed model (`src/sprint/speed.ts`, PURE, `test-sprint.cjs` + `test/unit/sprint-speed.test.ts`):** speed follows how often the legs ALTERNATE, never how high they go (2026-10-26, Martynas on a phone: slow but very high lifts "flew"; cause: cadence was an EMA of 1/Δt, Δt > 1.2 s was ignored and a same-leg repeat counted, so one left/right knee swap while a knee was held high (knees.json 12.9 s) doubled the cadence and the slow steps after it never lowered it). Now: same-leg repeats are ignored (still counted in `steps`), Δt < 0.12 s = one step, a gap > `DT_MAX` 1.5 s = stopped (the next step starts over); cadence = intervals / time over the steps of the last `WIN` 1.25 s (at least one interval), so one extra step moves it little and slow steps pull it down; once the next step is overdue it decays as 1/gap, 0 after `DT_MAX`. Target speed `v* = min(11.5, 2.6 × cadence)` m/s; speed eases toward it (τ 0.8 s up, 0.45 s down), acceleration capped at 6.5 m/s². Stopping from 4/s: 10.4 → 5.2 m/s after 1 s, ~1 m/s after 2 s. 10 m splits and the finish time are interpolated inside the frame (frame-rate independent). Steady cadence → 100 m: 1/s 40.5 s · 1.5/s 27.4 s · 2/s 20.8 s · 2.5/s 16.9 s · 3/s 14.3 s · 3.5/s 12.5 s · 4/s 11.1 s · 4.5+/s 10.3 s (cap). Real clips: knees.json slow high part (~1.1/s) 35.8 s (was 28.5), knees2 fast low knees (3.4/s) 12.9 s, knees3 (2.6/s) 17.2 s. Retune `K_SPEED`/`V_MAX`/`WIN` there and keep the test ranges honest.
- **Ghost (solo):** replays the 10 m splits of the best sprint in history (`ghostX`); without one, `simulate(2.8)` ≈ 15.2 s ("Tikslinis laikas").
- **History:** sprint games are normal `novacore.history` rows with `mode:"sprint"`, `times` (s, null = did not finish), `splits` (10 per player), `reps`/`exReps.knees` = steps, `score:[0,0]` (point records ignore them; streaks, weekly goal and knee totals count them). `histItem()` prints "Sprintas 100 m · solo/dvikova" with the times; `saveHist` is exported for this. - **Rendering:** one `<canvas>` (DPR ≤ 2, `alpha:false`). - **Rules (`logic.ts`, PURE):** space = mirrored screen space in frame-HEIGHT units (`X=(1-x)*ar`, `Y=y`). Body unit `u` = torso length (shoulder mid → hip mid, at least the shoulder width) or 1.3 shoulder widths when the hips are out of frame; shoulders (11, 12) are required. 7 slots in `u` from the shoulder on that side: high left/right, above the head, left/right at shoulder height, chest height outside the body; radius `R_U`=0.3 u (0.045–0.15), clamped (pad + timer ring) inside the player's half (P1 = left half, P2 = right half, solo = the whole frame) and below `G.top` (the HUD band, measured from `.bx-top` through the letterbox). Never on the last slot, on another pad or on a hand. Pace: life 2.0 → 1.2 s, spawn gap 0.9 → 0.4 s, 1 pad at a time for the first 30 %, then 2; nothing in the last 0.5 s. After `FIRST_SAFE`=5 s: 12 % bombs (never two at once), 8 % gold. **Hit** = the glove (wrist + 35 % of the forearm past it; the wrist alone without a visible elbow) SWEPT through the pad between two pose frames (segment-to-centre distance ≤ 1.15 r) with the decaying peak speed ≥ `MIN_SPEED`=1.6 u/s (punches 3–6 u/s, rest + detector jitter < 0.8), the pad armed (`ARM_S`=0.15 s after spawning), `HAND_COOL`=0.25 s per hand. Wrist/elbow below `VIS` or non-finite → that hand's history resets (a hand that reappears elsewhere is not a punch); shoulders lost → no hits for that player. Points: pad 10, gold 30, × combo multiplier `1+floor(combo/5)` (max ×4, counted before the hit); bomb −15 (floored at 0) + combo reset; an expired pad = miss + combo reset, an expired bomb = dodged, and a pad that expires while the player is out of view (`LOST_S`) is not a miss. Accuracy = hits / (hits + misses + bombs). Two players: poses are sorted by mirrored nose x; a lone pose in a 2-player game goes to the half its shoulders are in. Each player is only tested against their own pads, so a glove in the other half scores nothing.

- **Spec (Martynas):** run up to the line and jump before it; touching the line = the attempt does not score (foul); 3 attempts each, players take turns (everyone once, then the next round); longest jump wins; the distance comes from the take-off point (how close to the line) and the speed built up.

- **Ski model (`tick(skier,course,dt,input)`):** lean -> heading (`STEER_MAX` 0.35 rad, τ 0.16 s); v eases toward `GLIDE` 10 m/s (`DRAG_TAU` 3.6 s); one hand push adds `PUSH_V` 1.9 m/s (cap `V_MAX` 26 = ~94 km/h), both hands together ×`PUSH_DOUBLE` 1.6; leaning back targets `BRAKE_V` 4 m/s; deep snow targets ×0.55. Autopilot unit runs: 22.7 s at 1.4 pushes/s, 25.5 s at 1/s, 19.4 s at 2/s, 17.3 s at 3/s.
- **Camera controls (`readControl`; mirrored screen space, `u` = torso):** steer = `(shoulderMidX − hipMidX)/u`, full at `LEAN_MAX`=0.34 (dead zone 0.06). Brake = torso height / shoulder width below `BRAKE_ON`=1.02 (full 0.68) — leaning back shortens the torso in the front view. Each hand has its own stroke detector: a wrist dropping `PUSH_DIST`=0.08 u from its recent high, peak downward speed ≥ `PUSH_SPEED`=0.65 u/s, hand within `HAND_IN`=1.15 u of the body centre and below the shoulder; re-arms when it rises `PUSH_RETURN`=0.08 u (or above the shoulder), `PUSH_GAP`=0.18 s per hand. Both hands in one frame = one stronger push; alternating hands = one each. Missing / NaN / hidden landmarks = no input (the skier keeps gliding).
- **Drawing (`slope.ts`):** camera 14 m behind, 90 m of slope; perspective ribbon with a groomed centre line, red/blue boundary dashes, snow walls, pines, start line and a checkered finish with a "FINIŠAS" banner. Gates have striped poles and triangular flags (passed = dimmed, hit = fallen). Side marker poles every 12 m whip past outside the boundary. The skier is a back-view vector mascot standing on short flat ski boards (bindings/boots, tips forward), with poles from the gloves to the snow; skis splay when braking, the pushing hand pulls, snow spray, crash tumble; the camera x follows with a 0.22 s lag so carving reads. Speed lines, a snow streak layer and a high-speed edge vignette sell the speed; the sky / mountain backdrop is cached per resize.
- **HUD / results / history:** `#skRun` top = player card (name, big `km/h`, gate count), clock + live penalty, map with gate ticks + skier dot, `#skLive` gate count, a compact control legend for the first 9 s; a detected push flashes "Greičiau!" (`#skBoost`) and plays `sfx.push`; the camera becomes a smaller corner preview (`body.skiing #stage`). `#skEnd` = sunburst in the winner's colour, crowned mascot, rows with raw time / penalty / gates / crashes and green-yellow-red gate dots; "Čiuožti dar kartą" / "Į pradžią". History row: `mode:"ski"`, `times` (final incl. penalties, null = DNF), `skiRaw`, `skiPen`, `skiGates`, `skiMiss`, `skiHit`, `ex:["ski"]`, `score:[0,0]`, `reps` zeros; `histItem` prints "Slidinėjimas · N žaidėjai" with each time (3-4 players: the fastest). PB = the best final time on this phone. Not sent to Supabase.
- **TV:** `SKI.tv=true`; `begin()` sets `setScreenMode(tvState)` + `screenPhase("play")`, `finishRace()` → `"done"`, `reset()` → `"idle"`. The board shows the current skier + distance + gates, live metres as the score (2 players = both slots, 1 or 3-4 = the current skier), final times in 0.01 s on `done`, clean gates as reps and the 2-player winner. `ex.id:"ski"` → the skiing mascot demo.

## Languages / i18n (branch `en`, 2026-10-26)

- **Every user-facing string goes through `t()` and exists in BOTH `src/i18n/lt.ts` and `src/i18n/en.ts`.** That includes toasts, aria-labels, share texts, canvas text (sprint boards, "FINIŠAS"), error messages (`errText`, `duelErr`) and CSS-generated text (use `attr(data-…)` filled from `t()`, never a literal in `content:`). `en.ts` is `Record<Key,string>`, so a key missing in English fails `tsc`; `i18n.test.ts` catches empty values, different `{params}` and HTML text without a key. No i18n library.
- `t(key,{param})` fills `{param}`; plurals are one value with `|`: lt `one|few|other` ("{n} žaidimas|{n} žaidimai|{n} žaidimų"), en `one|other`, picked by `tn(key,n)` with `Intl.PluralRules`. Numbers with decimals: `dec(n,digits)` (12,34 / 12.34). Dates/weekdays: `locale()` (`lt-LT` / `en-GB`) + `weekday(day,"short"|"long")`; never hard-code `"lt-LT"`.
- `index.html` keeps the Lithuanian copy (fast first paint, readable markup). `src/i18n/dom.ts` (first import in `main.ts`) looks every text node and `aria-label`/`title`/`placeholder`/meta `content` up in `lt.ts` by its exact, whitespace-collapsed value and writes the current language; `<html lang>` and the manifest (`manifest.en.webmanifest`) follow. So a new or changed HTML text must be added to `lt.ts` with the SAME text (and to `en.ts`), or the test fails. Text that TS writes at runtime (counts, names) is not in the HTML: leave the element empty there. HTML built in TS (`sprint.ts`) uses `${t(...)}` directly.
- **Language choice:** `?lang=lt|en` (demos, wins over everything) > `localStorage novacore.lang` (Profilis → Nustatymai → Kalba LT/EN, `[data-lang]` in profile.ts) > `navigator.language` (`lt*` → LT, anything else → EN). Outside a browser (Node checks) it is always LT. Switching saves the choice and reloads with `?lang=` (every module builds its text once at load - no live re-render).
- **TV board follows the phone:** `ScreenState.lang` (room.ts clamps it to `lt|en`, missing = `lt` for older phones); `screen.ts` calls `setLang()` + `translateDom(#screen)` when it changes. Before the first phone message the TV uses its own `navigator.language`. The exercise name on the TV is the phone's (`ex.name`). Remote duels send no display text, so each phone simply shows its own language.
- Copy style: Lithuanian = the original text (keep it); English = short, playful, game-like (not literal). Mascots: Raudonas/Mėlynas = Red/Blue; Kompanijos = Crews; sprint countdown "On your marks… / Get set… / Go!". Check both languages at 360 / 390 px and landscape (`tools/screens.cjs --lang en --size 360x780`, `--landscape`): EN strings are usually shorter, but a few are longer (onboarding titles next to the mascot, the TV status pill).

## Conventions

- User-facing copy is Lithuanian first, English second: every new string through `t()` in both dictionaries (see **Languages / i18n**).
- MediaPipe is pinned to `@mediapipe/tasks-vision@0.10.14` in `package.json` (exact) and `MP_VERSION` in `src/camera/camera.ts` (wasm CDN URL for `FilesetResolver`), plus the `pose_landmarker_lite/float16` model URL (`POSE_MODEL`). Update version references together; `tools/extract.html` must use the same model as the game (`--model` exists only for comparisons).
- `sw.js` precaches `pose-samples.json` but serves it network-first, so a regenerated file reaches phones on the next online open.
- Styling and design tokens live in `:root` in `src/styles/main.css`; component rules use only `var()`/`color-mix()`. The design system is described in **Claude Design** above (tokens `--bw`, `--sh*`, `--r-*`, tones red/blue/yellow/ink, `.cam` dark remap with `--cam-*` and `--skel-p1/--skel-p2` read by `camera.ts`). Light is the product, no dark mode. Gutter 16px. Touch targets >=44px (small buttons extend the hit area with `::after`). Long Lithuanian labels must wrap (`overflow-wrap:anywhere` on names), never clip – check 360 px width.
  - Motion: transitions.dev / transitions-polish tokens in `:root` (`--duration-*`, `--ease-smooth-out`, `--ease-bounce`); press feedback = sink into the offset shadow in `--duration-press`; opening uses `--duration-slow`, closing `--duration-quick`/200ms; stagger `--duration-stagger`. `prefers-reduced-motion` collapses all animation.
- Icons: Lucide SVG paths copied into `src/ui/icons.ts` (ISC) – write `<span data-icon="name"></span>` in markup or `icon(name)` in code; add icons with `node tools/lucide-icons.cjs src/ui/icons.ts <all names>`. No icon fonts, no emoji. CSS ships unminified (`vite.config.ts` `cssMinify:false`) so no minifier can drop `-webkit-` prefixes; JS targets `esnext` (no down-levelling).
